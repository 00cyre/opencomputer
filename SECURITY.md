# Security model

OpenComputer is a local automation capability. An authorized agent can click controls that cause real external changes. The MCP client must obtain task authorization, distinguish instructions from untrusted app content, and require approval for consequential actions. The server does not understand business intent and cannot enforce a complete approval policy.

## Boundaries

- Empty app allowlist by default; exact bundle IDs checked inside the native helper on every app operation. The host can explicitly set `OPENCOMPUTER_APPS=*` for all running apps; operations remain scoped to one requested bundle ID/process. The agent cannot change this setting through an MCP tool.
- Entries ending in `:read` (including `*:read`) grant read-only access, checked in the helper before any element is resolved: observe, screenshots, `readText`, and launching work; every action and opening a URL fail with `READ_ONLY_APP`. An explicit `bundle:read` entry overrides `*`. Read-only access still sends what the app shows to the agent's model provider.
- Entries ending in `:click` (including `*:click`) allow `click`, `clickPoint`, `performAction`, `scroll`, and menu commands, and refuse `setValue`, `typeText`, `pressKey`, and URLs with `CLICK_ONLY_APP`. A click can still have real effects (Send, Delete, Buy); this level limits what can be typed, not what can be pressed.
- `*` and `*:click` never allow actions in the apps above the helper in its process chain (the terminal, editor, or chat app that started the agent): those are read-only and refuse with `HOST_APP_PROTECTED`, so an agent steered by injected content cannot press its own approval prompts or type into its own conversation. Naming the app explicitly allows it. The chain is read once at start from process parents; an agent host that launches the server through an unrelated process (such as `launchd`) is not detected.
- Snapshots are scoped to one process and bundle ID and expire 5 minutes after their last use. A full observe replaces the previous snapshot. Stale references fail closed.
- An action refuses (`TARGET_CHANGED`, `STALE_ELEMENT`) when its element's window title, selected tab, or web page differs from what the snapshot read, or the element left its window; the check runs again immediately before dispatch. `clickPoint` refuses when the screenshot's window title, size, or page changed. Changes the session caused itself are accepted unless the person was providing input at the same moment.
- Every request that touches an app is appended to a per-session action log (`~/Library/Logs/OpenComputer`, mode `0600`): time, method, resolved element role and label, app, window, tab, page address without query, and outcome. Typed text and values are reduced to their length. The log is an audit trail for the person, not a tamper-proof record: the same user account can edit or delete it. Each line carries a hash of the line before it, so `opencomputer log --verify` finds a line changed or removed inside a file, but not lines cut from the end, a deleted file, or a chain someone recomputed.
- Accessibility secure text values are redacted and actions on secure text fields are rejected. Ordinary fields and screenshots are not automatically scrubbed.
- Window captures are selected from windows owned by the allowed process. No whole-display screenshot command. A zoomed `region` stays inside the window of the app's previous capture. Element marks and OCR are computed on the Mac from that capture; recognized text and read text are returned to the agent but never written to the action log, which records only counts and lengths.
- `batch` is one MCP tool call that may perform up to 20 actions. All steps are validated before the first runs and it stops at the first error, but a client that asks for approval per tool call approves the whole batch at once. Clients that need per-action approval should not allow `batch`.
- No listener, remote endpoint, administrator privilege, global event-tap fallback, synthetic mouse events, clipboard-based typing, or locked-screen bypass. `open` launches only allowlisted apps and accepts only `http`, `https`, and `file` URLs.
- Node request timeouts close the native connection. Partial effects may already have occurred; observe before retrying.

The allowlist is not a sandbox against the calling process. A host with arbitrary shell access can start another helper with a different allowlist or automate macOS independently. Use your agent's tool permissions to restrict it. Local binary/config integrity and macOS permissions remain trust boundaries.

Key events are posted to the allowlisted target process only (`CGEvent.postToPid`), never to the login session, and carry their own modifier state. They reach whatever control has that app's own focus, so an agent with key access can drive anything in the app that a keyboard can, including shortcuts. Keys are refused while the app's focus is in a secure text field. `AXShowMenu` and `AXRaise` stay disabled. Before each action, a window-aware check protects editors the person is typing in, held mouse gestures and keys, recent input, and pointer proximity. It uses current OS state and event ages, not recorded keystrokes or input history. `USER_BUSY` means no dispatch and no queued replay. Annotation windows cannot become key/main and never reposition the user’s pointer; only the fully open activity card accepts clicks, for its own buttons.

Applications can still activate themselves in response to an action. The guard watches app activations during dispatch and for 1.5 seconds afterwards. An activation with no recent click, modifier, or key press from the person is treated as app-initiated, and the helper re-activates the app the person was in. This is the one case where the helper changes the foreground app, and it only ever returns to the previous one. A switch the person makes is left alone. The heuristic can misjudge: a self-activation that coincides with the person's own input is left in place, and a restored app can flash behind the other for a moment. A successful dispatch is never proof that a task completed.

Input silence cannot establish that a user has stopped reading. Preflight checks and dispatch are not atomic (a tab switch in the milliseconds between the final target check and the dispatch is not caught), and browser tabs share a window for conflict detection. These limitations cannot be fixed by silently falling back to global input or a different computer-control tool.

**Take over** and `OPENCOMPUTER_CONFIRM` approvals are enforced inside the helper: a paused session or an unanswered or denied question refuses the action before dispatch, and an answer is bound to the exact request it was asked about and used once. They are aids for the person at the Mac, not a substitute for the MCP client's own approvals. The `sensitive` rule matches button labels and a few keys; it cannot tell what an unlabelled or misleadingly labelled control does, and it does not cover typed text or values. Allow needs a half-second held press on the card and is not exposed as an accessibility action, so assistive and automation tools cannot grant permission through the accessibility API; the restrictive controls (Take over, Resume, Deny) are exposed. A program on the same login session that can synthesize a held mouse press at the button's position can still answer for the person, and a host that can restart the helper can change the setting. After Resume, the session's snapshots are dropped so the agent must observe what the person changed.

Agent labels and installed icons are display metadata, not verified identities. Session-stacking records contain only PID, timestamp, and expansion state in a per-user temporary directory. The visuals are not a security boundary; hosts can disable them.

## Reporting

Use GitHub's private vulnerability reporting if enabled on the repository. Otherwise contact the maintainer through their GitHub profile before posting exploit details publicly. Include version, affected boundary, minimal reproduction with disposable data, and expected/actual behavior. Never include API keys, tokens, private screenshots, or authentication logs.
